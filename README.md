# wxdump —— 微信 4.x 本地数据库「取钥 / 验钥 / 导出」通用小工具

> **使用范围(重要)**: 本工具只能在**你自己的电脑、你自己登录的微信账号**上运行,
> 用于恢复/备份**你自己的**聊天数据。请勿用于他人设备或账号。
> 全部动作在本地完成;聊天记录属于隐私,导出结果请自行妥善保管,不要公开或外传。

把「找到本地数据库 → 从运行中的微信进程恢复每库 SQLCipher 密钥 → 离线逐库验证 →
zstd 还原并导出聊天」整条链路做成一条命令,不写死任何账号或路径,换机器换账号也能用。

## 它解决什么问题

微信 4.x(xwechat 新架构)的聊天库在
`<xwechat_files>\<wxid_账号>\db_storage\` 下,是 **20 个左右、每个都用各自独立随机
AES-256 密钥 + SQLCipher 加密**的 `.db` 文件。密钥只存在于登录运行中的微信进程内存里,
不会以明文落盘;正文文本还要经过 **Zstandard 压缩容器**再入库。wxdump 把这几点串起来:

1. **find** — 自动发现 `xwechat_files` 数据目录、账号目录、正在运行的微信 PID
2. **keys**  — Frida 附加本机 Weixin.exe,在内存里按 codec_ctx 特征扫出每个库的
   codec,读出其 32 字节原始 AES 密钥与元信息,去重成候选集
3. **verify** — 枚举 `db_storage` 下每个 `.db`,逐库用 SQLCipher 离线验证
   `PRAGMA key = "x'<key>'"` 后能否读出 `sqlite_master`。**只有真正 PASS 的密钥
   才会被采用、写出、用于导出**;密钥与库的对应关系正是由这次真 PASS 归属的,
   绝无“猜一个当作对”。
4. **export** — 打开通过验证的库,把 `message_content` 里 zstd 帧解压还原、
   去掉发送者前缀、渲染系统消息,按会话(群聊/单聊/公众号)导出 UTF-8 `.txt` + 索引 CSV

## 安装

```bat
python -m pip install -r requirements.txt
```

需要:Python 3.9+;Windows 上运行微信 4.x(x64);本机装好 Frida 能附加的 Python 环境。

## 用法(推荐流程)

```bat
:: ① 先确认微信已登录运行,随便执行 find 看它找到什么
python wxdump.py find

:: ② 取钥(需要微信正在运行;PID/数据目录一般可自动找)
python wxdump.py keys --data E:\File\xwechat_files

:: ③ 验钥(离线、不碰进程;可保持微信运行)
python wxdump.py verify --raw keys_<账号>.raw.json

:: ④ 导出聊天记录 —— 建议退出微信后再导(WAL 已 checkpoint,最全最稳)
python wxdump.py export --verified keys_<账号>.verified.json

:: 或者 ②③④ 一把梭
python wxdump.py all --data E:\File\xwechat_files
```

### 微信在运行 vs 已退出(对导出的影响)

- **取钥(keys)必须**微信在登录运行(密钥在内存里,Frida 附加读)。
- **验钥(verify)**可运行时可退出,只读每库头几页;真 PASS 才算通过。
- **导出(export)自动检测**:
  - 微信**已退出** → 各库 WAL 已合并、文件静止,逐库做一次一致快照后导出(最完整);
  - 微信**正在运行** → 数据库处于 WAL 模式且可能正被 checkpoint 改写,工具会先对每库做
    SQLite **在线备份式一致快照**(在活库上开读事务、由 pager 协调 WAL,逐页拷到同密钥加密的
    新库),导出读快照,全程不干扰微信。若某库恰逢微信写盘高峰而反复快照失败,工具会如实
    中止并提示,请关闭微信后重跑——**绝不用撕页数据硬凑输出**。

### 参数说明

| 子命令 | 关键参数 | 含义 |
|---|---|---|
| `find` | `--data` | 指定 `xwechat_files` 目录(不指定则自动在磁盘上找);并显示微信当前正打开的账号 |
| `keys` | `--data --acct --pid --out --timeout --force` | `--acct` 过滤账号;`--pid` 手动指定微信进程;`--timeout` 扫描秒数(默认够用);`--force` 目标账号与当前登录账号不一致时仍继续(不推荐) |

> 实现说明: 4.x 库头不一定带可读的明文文件盐(实测 4.1.7.59 就没有)。工具因此**不把
> “按磁盘盐映射”当唯一途径** —— 它按路径枚举库,把内存里扫到的不同密钥作为每个库的
> 候选集;verify 阶段用 sqlcipher3 逐个真验,密钥与库的归属完全以 PASS 为准。
> 若某版本库头确有明文盐,会自动走“盐→库”精确命中,更快也更省事。
| `verify` | `--raw` | `keys` 生成的原始候选清单 |
| `export` | `--verified --out --self` | `--self` 仅在自动判断自己 wxid 失败时手动指定(形如 `wxid_xxxx`) |
| `all` | 见上 | 需要微信运行中 |

多账号: `keys --acct wxid_另一个` 会选对应账号目录。

## 中间文件

| 文件 | 内容 |
|---|---|
| `keys_<账号>.raw.json` | 每个磁盘库的候选密钥(来源: 内存 codec_ctx),**未经离线验证** |
| `keys_<账号>.verified.json` | **仅含 SQLCipher 真正 PASS 的密钥**(`key` 为纯 hex 字符串),是导出的唯一数据来源 |
| `export_<账号>/` | 每会话一个 `*.txt`(UTF-8)+ 每库 `index_*.csv` + `_summary.txt` |

## 输出格式

每个会话一个文本文件,首部为该会话元信息,之后每行一条消息:

```
[2024-05-01 09:12:33] 我[文本] 好的,马上到
[2024-05-01 09:12:40] 张三[文本] 我在门口了
[2024-05-01 09:13:01] 王五[图片]
[2024-05-01 09:13:10] 系统消息[系统消息] 「李四」邀请你加入了群聊,群聊参与人还有:…等5人
```

- 类型 1 文本消息正文被还原为真实内容(去掉 `<发送者>:` 前缀、zstd 解压还原);
- 图片/语音/视频/链接等以 `[类型]` 或简短标题占位;调用/位置等有短说明;
- 文件内不导出任何二进制。

## 已知边界 / 诚实说明

- **密钥只属于“正在登录”的账号**: 微信只把当前登录账号的库密钥加载进内存,所以
  `keys` 取到的密钥只对这个账号有效。工具会通过运行进程打开的 DB 句柄**自检账号**:
  `--acct` 与当前登录账号不一致时,**在扫描前就中止并说明**(避免拿 A 账号密钥去验 B
  账号库、白跑一轮);命令行不指定账号时自动改用当前登录账号。确需强行继续才用
  `--force`(结果将是 FAIL,不如先去微信登录目标账号)。
- **目标版本**: 在 4.1.7.59(x64,xwechat)上实测。微信若换架构/版本,内存里
  codec_ctx 的结构或加密方式可能变化——那时 `keys` 会**扫不到或验不过**,工具会如实报
  FAIL、**不会伪造 PASS**,请把失败信息发回,不要强行沿用。
- **空闲/未加载的库没有密钥可取**: 微信只把用到的库加载进内存,个别暂不打开的库
  (实测如 `migrate/unspportmsg.db`)没有 codec,verify 会对其如实 FAIL、不写入。
  导出只依赖联系人库与 `message_N / biz_message_N` 分片,不受影响。
- 库头若带可读明文盐则走精确命中;没有则自动改用“内存密钥全集逐库真验”归属。
  sqlcipher3 对错钥会往 stderr 刷 C 层日志,工具默认已静音(设 `WXDUMP_DEBUG=1` 可查看)。
- **实时性**: 取钥需要微信在登录运行;验钥/导出建议先退出微信,否则最新消息可能还在
  `-wal` 里没并入主库(主库内容仍可读,只是可能不是最新几条)。
- **媒体文件**(图片/语音/视频的真实文件)在另一套存储里,本工具只导出它们的消息记录与
  占位说明,不下载媒体本体。
- 群消息发送者显示依赖 `contact.db` 里能对应上的用户名;个别无法对应的显示为原始 wxid。
